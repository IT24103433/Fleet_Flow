# S4-10: Booking and maintenance CSV exports

Report pages now have a stationary Download CSV action using the existing Button, violet theme and Phosphor DownloadSimple icon. Filters and navigation are unchanged. Download requests are authenticated, uncached and cancelled when filters, accounts or routes change; duplicate clicks are guarded and failed requests never download HTML/error responses.

- `GET /api/reports/bookings/export?status=Cancelled`: Admin only. Includes every matching booking across pages, original IDs, current vehicle metadata, existing status, UTC dates and reserved LKR amount. A single bounded query reads the active booking owner. In Remote mode Fleet calls authenticated Rental `GET /internal/reports/bookings/export`; browser JWTs and unrelated service scopes are refused. Legacy mode reads Fleet-owned bookings. There is no automatic fallback to stale tables.
- `GET /api/reports/maintenance/export`: Admin, Fleet Manager or Maintenance Staff. Distinguishes current maintenance vehicle state from recorded activities using Record type. Includes persisted IDs, dates, costs and recorded history as JSON; unknown fields stay blank. Unavailable work-order data returns 503, not a partial CSV.
- Both return UTF-8 CSV with BOM, CRLF, quoted/escaped fields and attachment filenames. Dates are ISO UTC; numeric amounts use invariant formatting. Text beginning with formula markers, including full-width variants or control prefixes, receives a quoted tab prefix for spreadsheet viewing, following [OWASP's Excel guidance](https://community.owasp.org/attacks/CSV_Injection). This intentionally changes dangerous text cells; exports are viewing files, not database backups. No universal spreadsheet/re-import safety guarantee is implied.
- Exports exceeding 10,000 rows are rejected without truncation. Invalid filters return 400, missing/unauthorized access 401/403 and unavailable sources 503. No schema changes, data writes, new libraries or deployment configuration are required. Rollback is the previous frontend/API artifacts; exported files do not change stored records.

Validation: 577 backend tests and 138 frontend tests passed with no skips on this branch's develop baseline. New coverage exercises report permissions, all filtered rows beyond the first page, formula/quote/newline escaping, locale-independent amounts, unknown costs, oversized/unavailable data, Rental ownership/authentication, download guards and cancellation. Lint, production build and diff checks passed. Entry/static-import JavaScript is 303,332 bytes; lazy report routes are measured separately in s4-10-verification.json.

One desktop Browser review at 1440 × 900 verified the real booking download and unchanged report layout. Both export APIs returned CSV through four isolated services using restored database copies (four bookings and sixteen notifications). No working database, upload, Azure fleet or deployment was changed. Mobile/tablet testing was skipped. Evidence: docs/review/s4-export-bookings-1440.jpg.
